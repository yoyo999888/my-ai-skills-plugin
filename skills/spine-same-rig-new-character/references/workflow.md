# 流程细节与参数

以下取值都是云汐案例实际用过、验证过的。坐标约定：

- 世界坐标 x 右、y 上；
- 附件"图像坐标"以原附件 orig 尺寸的像素为单位，u 右、v 下；
- 画布像素 `px = (x - cx) * S + W/2`，`py = H/2 - (y - cy) * S`。

## 0. 盘点

- 骨架转成标准 Spine JSON（skel 只能读时，用 spine-c 导出或桥接），并与原 skel 在官方 C 运行库上比对全部动作的骨骼坐标，确认转换无损。
- 按规格提取每个区域：
  - `rotate: true` 的区域：`crop = page[y:y+w, x:x+h]; img = crop[::-1, :].transpose(1, 0, 2)`；
  - 按 orig / offset 贴回原尺寸时，offset 以左下为原点：`top = oh - oy - h`。
  - 提取后用自写光栅化器合成一帧，和官方渲染逐像素比，平均差 < 0.012 才算提取正确。
- 统计表（每个动作按 30 Hz 采样）：
  - 每个 slot / 附件的可见帧数；
  - 头部正、侧、背三个 slot 各自出现的时间段；
  - 骨骼时间线里 |shear| > 60° 的骨骼和动作（翻身用）；
  - `root` 和最顶层骨骼的位移范围（带整体位移的动作）。
- 五官骨骼（眼、嘴）在全部动作中只有 0 值关键帧 → 五官不单独做部件，画进脸里，原五官 slot 留空。

## 1. 人台

- 待机第 0 帧；画布 1120×1400、S=6.7 像素/单位，让角色高度约占 85%。
- 每个 slot 的轮廓：原 alpha > 0.3 → 填洞 → 开运算 1 次 → 高斯 0.7。按材质给灰度（头发 0.27、皮肤 0.88、白衣 0.96 等），描 2 像素深色边。
- 新增形状画在所属附件的图像坐标里：
  - 双环髻：两个环，挂在头部附件上；
  - 直剑：剑首、剑柄、护手、剑身四个多边形，挂在原武器附件上，画布从 26×59 扩到 26×74。
- 保存每个 slot 的完整轮廓（uint8）和"最上层归属图"（每个像素属于哪个 slot），切图和回绑都用它。

## 2. 设计稿

- 第一次调用：参考图只有人台。提示词写清画风、角色设定、每个灰块代表什么；还要写"不要像某某"的排除项（原角色的发色、服装配色、标志性饰物）。
- 第二次调用：参考图 1 = 平涂色块图（按第一次结果取的配色，五官占位按原眼、嘴部件的图像坐标画），参考图 2 = 第一次结果。
- 检查项：
  - 轮廓 IoU（人台 vs 设计稿，alpha > 0.5）：0.91 → 0.94；
  - 部件边界叠到设计稿上看，发丝、袖子是否落在对应部件里。

## 3. 部件图纸

- 像素分类（HSV）决定哪些设计稿像素可以预填：
  - 深色：v < 0.38，或蓝紫色调暗部（h 200–300、v < 0.62）；
  - 白：v > 0.86 且 s < 0.10；肤：h 8–42、s 0.06–0.42、v > 0.72；
  - 粉、红、玉、金属同理。
- 每类部件只接受对应的像素类，例如头发只要深色、皮肤接受肤色和粉色；另外放行部件外轮廓 4 像素内的深色描边。开运算 1 次，丢掉小于 40 像素的碎块。
- 头部用 `fill_all`：整个轮廓内都采用设计稿像素。
- 其他视角采来的身体部件用 `fill_visible`：只采用可见部分。
- 排版：
  - 画布 1400×1120（配合 1536×1024 请求），部件间距 18，标签高 20，标签放在部件最高点上方；
  - 用二分法找最大放大倍数（上限 1.8×）；
  - 同时保存每个部件在图纸上的轮廓 PNG 和标签框，提取时要用。
- 实际分了 4 张：头发与头、上身与手臂、裙、腿鞋剑飘带。并行调用，每张约 55 秒。

## 4. 回绑

- 贴图密度：K = 7 像素/图像单位，脸部用 9。
- 取像素：
  - 部件轮廓外扩 7 像素作为采样范围，排除所有标签框；
  - 去投影：轮廓外 3 像素以上、半透明（alpha < 0.85）或偏暗（亮度 < 0.35）的像素丢掉；
  - 用预乘双线性采样。
- 区域附件：新画布范围 (u0, v0, u1, v1) → 按附件的旋转和缩放算出中心偏移，得到新的 x / y，宽高 = 范围大小。
- 网格附件：
  - 在新贴图上铺 3.5 单位的方格，只保留 alpha > 0.02 的格子（外扩 1 格），对角线交替；
  - 新顶点的权重：在原网格里找包含它的（或最近的）三角形，按截断后的重心坐标混合三个原顶点的影响骨骼；三角形外的点，把"外推位置 − 截断位置"的差转到各骨骼的局部坐标里加上；
  - 每顶点最多保留 8 根骨骼并归一化；
  - 校验：绑定姿势下蒙皮结果 vs 分段仿射外推位置，最大误差应 < 0.01（实测 0.005）。
- 贴图收尾：
  - 去掉小于最大连通块 2% 的碎片；
  - alpha < 0.03 置 0；
  - 把颜色向透明区扩散 10 圈，避免线性过滤出黑边。

## 5. 其他视角

- 模板骨架：已完成部件用新贴图；还没画的部件用原 alpha 放大 7 倍 → 平滑 → 填洞 → 平涂 + 描边作占位，头部占位也画上发髻。
- 选一帧该视角清楚的姿势（背面选攻击一 1.3 秒，侧面选瞬身斩 0.63 秒），画布 1254×1254，按该视角部件包围盒 × 1.45 取景，请求 1024×1024。
- 用 Python 光栅化模板骨架，得到每个 slot 在该画面的轮廓和可见区域，再按第 3 步做补全图纸，这张图纸可以混合多个来源画面。
- 张开的手等只在特定动作出现的附件，用该动作的一帧作为来源。

## 6. 展开空间重画（折叠部件）

- 找折叠：对网格每个三角形比较图像空间和绑定姿势世界空间的有向面积，同号即翻面；按不透明度加权，翻面比例高的部件（纱袖 31%、长发 8%）要重画。
- 模板：原部件 alpha 放大（多个部件时约 7 像素/单位，单个大部件可到 13）→ 闭运算 → 填洞 → 高斯平滑。
- 预填：现有贴图里未折叠区域（翻面三角形外扩后排除），再腐蚀 3 像素。
- 回绑：纹素 ↔ 图纸是简单的缩放平移，不经过姿势映射；网格按第 4 步重建。
- 裙摆在蹲伏时会被原动作压扁成一条线：把底部 22% 的范围渐变淡化（向白色混 65%，alpha 降到 0.8）。

## 7. 特效

- 蓄力光弧序列帧：12 帧，K = 2.5；每帧 4 条旋转光弧（核心白 + 青/粉辉光）加少量火花，按帧淡入淡出。
- 光点：K = 4，核心 + 光晕 + 四芒星。

## 8. 输出与构建

- 图集：货架式打包，2048 页，间距 4。区域附件裁透明边后写 `orig` / `offset`，网格附件不裁。
- 所有后处理都写进构建配置，逐项开关：
  - 贴图替换 `override_textures`；
  - 前层裙 `front_skirt`；
  - 鬓发移到脸后 `lock_behind_face`；
  - 侧面隐藏一缕头发 `side_hide_lock`；
  - 侧面脖子 `side_neck`；
  - 裙摆淡化 `soften_hem`。
- 替换贴图要从"基础构建"出发：先关掉替换跑一遍，取出原贴图 → 跑修复脚本 → 再正式构建。重建脚本按这个顺序写，最后比对输出哈希。

## 9. 局部修复手法

- **脸侧残留头发**：
  1. 找区域：把鬓发 slot 在该画面的轮廓反投影到头部贴图，取范围内、眉线以下的深色像素，加上每一列脸部皮肤最低点以下的深色像素；排除眼睛椭圆和对侧头发。
  2. 做模板：区域内下颌曲线以上填脸颊中位肤色，以下清空；放大 2.4 倍放在灰底上交给模型重画。
  3. 对齐：在没改动的区域（另一只眼、嘴）上网格搜索 ±6 像素，再细到 0.25 像素。
  4. 贴回：用羽化掩码在预乘空间混合。
- **下颌切口**：沿现有轮廓取 Catmull-Rom 平滑路径，4 倍超采样切掉路径下方 1.2 像素以外的部分，在原来接着残块的那段补 2.4 像素描边。
- **侧面脖子**：画在侧面头部贴图的坐标里。喉咙线从下巴最低点之后的下颌底部起笔、向下略微后收；下颌下方 16 像素做阴影渐变，前后缘描边；显示时间线复制侧面头部 slot。
- **发根尖角**：直线斜切，切口描 2.2 像素边。
- **只在某时间段隐藏**：复制成新 slot，删掉时间窗内的附件关键帧，在起点加"不显示"、终点加"恢复"。

## 10. 验收

- spine-c 小工具：读 JSON + 图集，按 `动作 时间` 逐行输出绘制列表和骨骼端点。新旧两套在全部动作 60 Hz 采样下比较骨骼坐标（实测差 0）；抽 8 个姿势比较 C 和 JS 的顶点（实测最大差 0.0001）。
- 绘制顺序：从 JS 渲染信息里读每个姿势的 slot 顺序（30 Hz，638 个姿势）。原 slot 相对顺序 0 处不同，4 个新 slot 全部在预定位置。
- 联系图：每帧用 C 运行库算出髋骨位置取景；整帧空白的格子标"原动作隐身段"。
- 纹素可见性统计：目标部件贴图写入 (u, v, 部件码)，其余部件涂黑、黑底渲染全部帧，读回像素就知道每个纹素在哪些帧露出。
- 播放器测试：加手动步进模式（关掉 rAF 驱动，按 1/30 秒调 `frame(dt)`），Playwright 截舞台区域，ffmpeg 合成视频；从日志检查动作序列和角色位置，看切换处的逐帧条带。

## 成本参考

- 生图 13 次，每次 45–65 秒，累计约 735 秒，全部一次成功、没有自动重试。
- 一次组装约 12 秒；从生图原件完整重建（含验收）约 2 分钟。
