# 问题手册（本案例实际遇到的）

每条按"症状 / 原因 / 怎么发现 / 怎么修"写。前四条是用户亲自挑出来的，交付前务必自查。

## 用户挑出来的

### 1. 腿画在裙子外面
- 症状：待机、跨步时，白色裤腿压在长裙上。
- 原因：原角色的长裙是开衩裙的**后片**，绘制顺序在腿后面。新设计是整片长裙，却沿用了后片的层级。
- 发现：待机和大跨步的下半身特写；列出每个 slot 在绘制顺序里相对腿组的位置。
- 修：新增前层裙 slot，插在腿组之后、上身之前；附件和显示时间线移过去，原 slot 留空。核对全部姿势：原 slot 相对顺序不变，新 slot 紧贴在腿组上一层。

### 2. 脸上残留一缕头发
- 症状：鬓发摆开后，脸上还留着一缕黑发；受击甩头时，鬓发盖在嘴上像胡子。
- 原因：头部是从设计稿里按"头部轮廓"切的，而会单独摆动的鬓发正好压在脸上，被一起切进了头部贴图。原动作在受击时会把鬓发甩过嘴。
- 发现：各动作的头部特写，把"只显示鬓发"和"不显示鬓发"分别渲染对比；把鬓发 slot 的轮廓反投影到头部贴图上看重叠。
- 修：头部贴图只重画耳前那块（见 workflow.md 第 9 节）；鬓发移到脸的下一层（新 slot，插在头部 slot 之前）。
- 预防：图纸的头部说明里写明"单独摆动的发束不在头部部件里"；切头部时扣掉所有叠在上面、会单独运动的部件区域。

### 3. 下巴下留一截脖子
- 症状：正面下巴左下方挂着一小块皮肤。
- 原因：头部贴图从设计稿里带出了下颌以下的皮肤（脖子）。
- 发现：头部贴图下缘放大查看；打印像素分类字符图（透明 / 轮廓 / 皮肤 / 头发）。
- 修：沿现有下颌轮廓切掉下方部分，补画描边。**每个视角**（正、侧、背）的头部贴图都要检查。

### 4. 侧面视角下巴下露出黑发
- 症状：瞬身斩侧面那几帧，下巴下面有一块黑色楔形。
- 原因：原角色侧身上衣（侧面躯干 slot）的顶部画的是宽脖子加宽领口，正好挡住长发发根；新角色是窄高领，于是发根露了出来。原角色的发色浅、半透明，所以当时不显眼。
- 发现：用 UV 编码贴图渲染，查出楔形来自哪个部件的哪些纹素；把原角色的侧身上衣轮廓叠到新画面上对比。
- 修（按效果排序）：
  - 加侧面脖子 slot：画在侧面头部的坐标里，喉咙线从下颌底部起，时间线复制侧面头部。
  - 发根伸向前方的小尖角斜切。
  - 只在侧面段隐藏那一缕头发：复制成新 slot 并改显示关键帧，原 slot 不动。
- 教训：脖子画得太宽（从下巴尖直接往下）会重新变成"下巴下挂一截"。喉咙要从下巴最低点之后起笔。

## 美术与切图

### 5. 孤立部件装配：比例、朝向对不上
- 反例做法：让模型画竖直摆放的独立部件，再按锚点装配。部件的朝向、比例和重叠关系与原动作的实际姿势不一致，只能靠额外的修正轨道补救。
- 做法：在骨架的姿势里画整体，再按 slot 轮廓切图（本技能主流程）。

### 6. 折叠部件在姿势图纸上怎么修都坏
- 症状：前臂纱袖的上端破碎、带暗色碎片；换一张图纸重画，结果依旧。
- 原因：绑定姿势里这块网格的部分三角形是翻面的，"姿势画面 → 贴图"的映射是多对一，图纸上画得再好，提取回贴图也会被折叠区打乱。
- 发现：统计每个网格在绑定姿势下的翻面三角形比例（图像空间与世界空间的有向面积同号即翻面）。
- 修：改在贴图的展开空间里重画（workflow.md 第 6 节）。

### 7. 裙摆在蹲伏时被拉成一条条细线
- 原因：原动作在大跨步、倒地时，会把裙网格底部压扁到很窄。原角色同一处也这样，只是深色半透明的纱不明显。
- 修：
  - 裙子重画时要求褶皱用"浅、宽、低对比"的阴影，不要深色细线；
  - 底部 22% 渐变淡化；
  - 在说明文档里写明这是原动作的限制。

### 8. 模型的"额外发挥"
- 投影：在部件下方画柔和阴影 → 取像素时丢掉轮廓外半透明或偏暗的像素。
- 标签：图纸上的文字被采进贴图 → 采样时排除所有标签框（整张图纸的，不只是当前部件的）。
- 参考部件被改：同一张图纸上"当参考别改"的部件，模型也会重画 → 只采用目标部件。
- 局部重画时改动别处（耳坠变大）→ 只按修复区域的羽化掩码贴回。

### 9. 线性过滤出黑边
- 修：保存图集前，把颜色向透明像素扩散 10 圈。

## 绑定与层级

### 10. 新增 slot 破坏原绘制顺序
- Spine JSON 的 drawOrder 关键帧只记录偏移；没列出的 slot 按原顺序填补剩下的位置。
- 插入新 slot 时，要先按这个规则还原每个关键帧的完整顺序，把新 slot 插在"相对某个 slot（或某组 slot 中的最前/最后一个）"的位置，再重新算全部偏移（`scripts/slot_ops.py`）。
- 插完用渲染信息逐帧核对：原 slot 相对顺序 0 处不同，新 slot 在预定位置。

### 11. 拆好的部件图方向错
- 症状：自写光栅化器合成出来和官方渲染对不上，差异集中在旋转区域的网格附件上。
- 原因：`rotate: true` 区域的转回方向错了（已有的部件拆图就是错的）。
- 修：按运行库约定重新提取，合成结果与官方渲染逐像素对比。

## 播放器

### 12. 动作过渡时人被压成一条线
- 原因：原动画用 180° 错切做翻身，交叉淡入时错切按线性插值，中途经过 90°，骨骼矩阵退化。
- 修：淡入期间，凡是错切与目标动作相差超过 45° 的骨骼，直接取目标动作的局部变换。这个处理在播放器里；接入游戏引擎时要同样处理，或者这几组动作之间不做淡入。

### 13. 带位移的动作播完后镜头方向反了
- 原因：spine-ts 3.4 的 `skeleton.x` 只在顶点阶段叠加，骨骼 `worldX` 里没有它。镜头跟随如果读骨骼坐标，就会漏掉角色位置。
- 修：镜头用 `bone.worldX + skeleton.x`；画骨骼调试线时同样要加上。

### 14. 其他
- 位移动作播完瞬间弹回原位 → 把最终位移并入角色位置，再跑回去。
- 击倒后直接消失 → 3.4 的状态机会在 endTime 后清空非循环轨道，要把 endTime 延长。
- 上一个动作的特效残留 → 切换时，把新动作没有控制的 slot 重置为初始附件和颜色。
- 画面抖 → 不按包围盒逐帧缩放，改为固定缩放 + 死区 + 阻尼跟随。
- 跳起时头顶出画 → 纵向硬边界要比横向收得更紧。

## 工具与接口

- `scipy.ndimage.binary_dilation(mask, iterations=0)` 表示"膨胀到收敛"，会把整张图变成 True。要写 `if d > 0:` 再调用。
- numpy 整数直接 `json.dump` 会报 int64 错误，写 JSON 前先转成 int。
- WebGL1 只有 2 的幂尺寸的贴图能开 mipmap。`GLTexture(gl, img, useMipMaps)` 按尺寸决定是否开启；另外，3.4 版本的 `TextureFilter` 枚举不能直接当 `setFilters` 的参数用。
- 无头 Chrome 渲染 WebGL：启动参数 `--use-angle=swiftshader --enable-webgl --ignore-gpu-blocklist`，上下文开 `preserveDrawingBuffer: true`。
- 离线网页会自动请求 favicon，报 404 → 加 `<link rel="icon" href="data:,">`，控制台就干净了。
- 生图返回尺寸不等于请求尺寸；返回的 quality 字段写 medium 也不代表按 medium 生成，不要依赖。

## 验收

- 数值通过不等于好看。骨骼差 0、顶点一致、权重合法，都发现不了"层级语义错"和"部件画进了别的部件"。上面 1–4 全是看图才发现的。
- 联系图要按每帧髋骨位置取景：带位移的动作用固定镜头会跑出画面，容易误判成"缺图"。
- 用户会看特写：交付前先自己看一遍脸、下巴、脖子（正/侧/背）和腿裙的放大图。
