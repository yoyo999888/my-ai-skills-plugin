# spine-same-rig-new-character

已跑通的案例：烟雨江湖 `bainani`（Spine 3.4.02，131 骨骼 / 78 slot / 21 动作）→ 仙侠卡通女剑客"云汐"。共 13 次生图；骨骼、IK、动作曲线、原 slot 定义和时间线逐字段不变；官方 C 运行库全动作 1237 个姿势骨骼坐标差 0；只新增 4 个图层修穿帮。

**核心做法：让部件在骨架的姿势里被画出来，而不是先画孤立部件再往骨架上装。**
反例（同项目 codex 版）：让模型画一个个竖直摆放的部件，再按锚点装配。比例、朝向、重叠和实际动作对不上，最后只能靠额外的动画修正轨道补救，用户评价"粗糙、形象和动作不匹配"。

## 何时使用

- 手上有一套能被官方运行库加载的 Spine 运行时数据（JSON，或 skel + 可导出 JSON），要做一个外观完全不同的新角色，并且直接复用全部动作。
- 生图接口支持"图片编辑 + 多张参考图 + 透明背景"（实测 `gpt-image-2.5` 的 `/images/edits`，`input_fidelity=high`）。
- 需要 Python（Pillow / NumPy / SciPy）、Node + Playwright、本机 Chrome，以及同版本的官方运行库（spine-webgl，最好再有 spine-c）。

不适合：身体结构不同（多手、四足）、必须改骨长或动作的情况——那是重新绑定，不是这个流程。

## 步骤

详细参数和判断标准见 [references/workflow.md](references/workflow.md)，提示词见 [references/prompts.md](references/prompts.md)。

0. **盘点骨架**：列出 slot→骨骼→附件表；按动作统计每个附件在哪些帧可见；找出视角切换（正/侧/背头部各是哪些 slot、在哪些时刻切）、特效 slot、用 180° 错切做的翻身；检查五官骨骼相对头部是否会动——不动就把五官并进脸，只画一张脸。
1. **做人台**：用官方运行库渲染待机第 0 帧。每个 slot 按原 alpha 的实心轮廓、按材质分灰度画出来；新设计要多出的形状（发髻、换形的武器）直接画进人台。同时保存每个 slot 在这个画面里的完整轮廓和可见区域，后面切图要用。
2. **设计稿，分两次画**：
   - (a) 人台 + 文字设计 → 模型把人台"上色"成新角色，要求保持位置和轮廓；
   - (b) 按 (a) 的配色把人台平涂，按原眼嘴位置画五官占位，再以 (a) 作风格参考重画一次。第二次对齐明显更好（轮廓 IoU 0.91→0.94）。
3. **部件图纸**：每个部件按它在姿势里的朝向裁出。设计稿里材质对得上的像素直接预填，被遮住的部分平涂提示色，加描边和小标签。紧凑排版、整体放大铺满画布。4 张图纸并行交给模型补全。
4. **回绑到原附件**：把图纸像素映射回每个附件自己的图像坐标，得到画布扩大了的新贴图。区域附件直接仿射；网格附件在绑定姿势下按三角形分段仿射。
   - 区域附件：重算 x / y / 宽 / 高。
   - 网格附件：在新贴图上重建网格，权重用原网格的重心坐标迁移过来（`scripts/mesh_rebind.py`），并验证绑定姿势重算误差 < 0.01。
5. **其他视角**（背面、侧面头部等）：拼一个"模板骨架"——已完成部件 + 还没画的部件用平涂占位。摆成背身/侧身姿势渲染，让模型在这个画面里只补画占位部分，再切出来做补全图纸。这样三个视角风格一致。
6. **动作中会折叠的部件**（绑定姿势里有三角形翻面的长发、纱袖、长裙）：改在贴图的展开空间里重画。模板 = 原部件轮廓平滑后的形状，预填没有折叠的区域。
7. **特效**（additive / screen 混合的序列帧、光点）：直接程序生成，沿用原附件几何。
8. **打包输出**：图集（区域附件可裁透明边并写 offset）+ JSON。骨骼、IK、动作、原 slot 定义和时间线保持原样。
9. **修穿帮**：只用新增 slot，不改原数据（见下节）。
10. **网页播放器、验收、录屏**（见后两节）。所有后处理写成配置 + 脚本，保证能从保存的生图原件重建出逐字节相同的结果。

## 修穿帮：只加新 slot，原数据不动

| 症状 | 原因 | 做法 |
|---|---|---|
| 腿画在裙子外面 | 原长裙是开衩裙的后片，排在腿后面 | 新 slot 插在腿组之后、上身之前；附件和时间线移过去，原 slot 留空 |
| 脸上残留一缕头发 | 切图时把单独摆动的鬓发画进了头部贴图 | 头部只重画耳前那一块（平涂肤色→模型局部重画→按掩码羽化贴回，眼睛耳坠像素不动）；鬓发移到脸的下一层，受击甩头也不遮脸 |
| 下巴下留一截脖子 | 头部贴图带着下颌以下的皮肤 | 每个视角的头部贴图都切到下颌线，并补这段轮廓 |
| 侧面下巴下露出黑发 | 原角色靠侧身上衣顶部的宽脖子、宽领口挡住；新角色是窄领 | 加一个只在侧面显示的脖子 slot（喉咙从下颌底部开始）；该缕头发只在侧面那几帧隐藏（复制成新 slot，改显示关键帧） |

`scripts/slot_ops.py` 插入 slot 时会按 Spine 规则还原每个 drawOrder 关键帧，保证原 slot 之间的相对顺序不变。插完要在全部采样姿势里核对。

## 播放流畅的要点

- 用官方 AnimationState 做动作间交叉淡入。非循环动作播完回待机；击倒类动作停在最后一帧——3.4 版本会在 endTime 之后清空轨道，要把 endTime 延长。
- **原动画用 180° 错切做翻身**：交叉淡入时插值会经过 90°，人被压成一条线。解决办法：淡入期间，凡是错切和目标动作相差超过 45° 的骨骼，直接取目标动作的姿势。
- 带整体位移的动作（闪避、突进、瞬身）：播完把位移并入角色位置，再用前移/后撤循环跑回原位，不要瞬间弹回。
- **spine-ts 3.4 的 `skeleton.x` 不计入骨骼 worldX**（只在顶点阶段叠加），镜头跟随时要自己加上。
- 镜头：固定缩放 + 死区 + 阻尼 + 硬边界。不要按包围盒逐帧缩放，画面会抖。
- 切换动作时，把新动作没有控制的 slot 重置为初始附件和颜色，避免特效残留。

## 验收清单（以看图为准，数值通过不等于好看）

- **结构**：骨骼、IK、骨骼时间线、原 slot 定义与时间线逐字段相同；新增 slot 单独列出。
- **官方运行库**：C 运行库加载新旧两套数据，全部动作按 60 Hz 采样，骨骼世界坐标差 = 0；C 与 JS 顶点差 < 0.001。
- **绘制顺序**：全部采样姿势里原 slot 相对顺序不变，每个新 slot 在预定位置。
- **看图**（用户最先挑的就是这些）：
  - 全动作联系图（以髋骨为中心取景，原动作的隐身段要标出来）；
  - 正/侧/背每个视角的脸、下巴、脖子特写；
  - 大跨步和倒地时的腿与裙；
  - 动作切换的逐帧条带；
  - 录屏视频抽帧。
- **离线网页**：单文件在 `file://` 下打开，无报错、无外网请求。
- **可重建**：从保存的生图原件重建，输出哈希一致。

## 常见坑（详见 [references/pitfalls.md](references/pitfalls.md)）

- 图集里 `rotate: true` 的区域要按运行库约定转回；网格 UV 对应打包矩形，libgdx 的 offset 以左下为原点。别人已经拆好的部件图可能方向是错的——自己重新提取，并与官方渲染逐像素对比。
- `scipy.ndimage.binary_dilation(iterations=0)` 会一直膨胀到收敛，不是"不膨胀"。
- 图纸上的文字标签、模型自己加的投影会被采进贴图：取像素时排除标签框，去掉轮廓外半透明的暗色像素。
- 放在图纸上"当参考、别改"的部件，模型也会顺手改掉：只采用目标部件。
- 要裁掉某块贴图之前，先做"纹素可见性统计"，确认它在其他帧里看不见。
- 生图请求 1024×1536，实际返回 1121×1403；要缩放回图纸尺寸。返回里的 quality 字段不可信。

## 脚本

- `scripts/render_spine.cjs`：无头 Chrome + 官方 spine-webgl 渲染任意姿势，输出 PNG 和每个 slot 的世界坐标多边形。人台、对照、联系图、可见性统计都靠它。
- `scripts/slot_ops.py`：插入新 slot（位置相对已有 slot 或一组 slot）、移动附件、复制时间线、在某个动作的时间窗口里隐藏；不破坏原绘制顺序，带自检。
- `scripts/mesh_rebind.py`：新贴图上建网格，把原网格权重按重心坐标迁移过来，附带绑定姿势误差校验。
