# Reasonix 调度与任务包

本文件供调度者在任何变更、多文件任务、并发任务或返工任务投递前使用。Reasonix 是执行者；
调度者负责把事实、决策和验收合同冻结成可独立完成的任务包。

## 1. 拆包门

只有同时满足以下条件才进入 DISPATCHABLE：

- 只有一个可观察结果；
- 所有验收项属于同一个失败域，并共享同一运行序列或 fixture；
- 可以独立回退、复测和验收；
- 架构、兼容语义、阈值、范围和 PASS 定义已经由调度者裁决；
- 允许路径、禁止路径和非目标明确；
- 基线事实已经确认，不依赖执行者猜测穷举集合或调用契约。

遇到以下情况必须拆分：

- 一个提示同时包含生命周期、业务语义、诊断、汇总或文档等不同失败域；
- 某一部分失败时，其他部分仍可能独立合入；
- 验收需要不同环境、不同 fixture 或不同权限；
- 多个执行者会写同一文件或同一 worktree；
- 提示要求执行者“全面考虑”“自行设计”“顺便修复”未裁决事项。

不要按文件机械拆包。一个行为可能跨多个文件；相反，同一个大文件里的不同运行序列也应拆开。

若事实不完整，先派 inventory。例如先只读列出所有车型键、入口与 nil/损坏值调用契约，再由调度者
裁决允许集合；不要把盘点、架构选择、实现和验收塞进同一轮。

## 2. 任务类型

- **inventory**：只读事实盘点。交付出处、反例、未知项；不修改、不裁决。
- **implement**：实现冻结合同。允许局部工程选择，不允许改变合同。
- **test**：实现或运行明确判据。不得修改门槛以迁就当前实现。
- **mechanical-review**：给候选 finding 与置信度。所有 finding 均为待调度者复验。

先分类，再选模型与超时。便宜快速模型只承担原子任务；复杂任务优先继续拆分，而不是把规划责任
交给更长的无人值守提示。

## 3. 基线与权限

调度者在投递前记录：

- worktree 与分支；
- 基线 commit；
- 初始 git status；
- 已知基线失败及复现命令；
- 允许修改和允许新增的路径；
- 禁止修改的路径与外部系统；
- 是否允许 commit、push、启动服务、操作 GUI 或真实环境；
- 任务时间预算与单测时间预算。

变更结束后对照起始快照检查越界文件、意外未跟踪文件和新增基线失败。Reasonix 的工作目录不得放
隐藏判分器、参照答案、其他执行者日志或进度文件。

## 4. 标准任务包

~~~text
类型：
单一目标：

基线：
- worktree / branch：
- commit：
- 已知失败：

已裁决事实：
- ...

实现合同：
- 明确输入、状态变化、输出和失败语义
- 明确哪些 nil / 损坏值 / 边界值合法

允许修改：
- ...

禁止与非目标：
- ...

反例：
- 旧实现必须如何失败
- 修复后必须如何通过

自测：
- 命令：
- 期望退出码：
- 时间预算：
- 证据级别：static / mock / engine / live

交付：
- 实际 diff
- 命令、退出码、耗时
- 未运行项与剩余风险
- 状态只能是 SELF_TESTED、BLOCKED 或 FAILED
~~~

实现合同不要写成“自行全面修好”。调度者应给出事件顺序和不变量，例如“先确认停稳，成功后才按
倒车键；停稳失败时不得产生输入副作用”，而不是只给最终状态。

## 5. 测试与证据

- 先验证判分器有效：坏版本或临时 mutant 必须失败；随后恢复现场，最终不得残留 mutant。
- 反例由调度者定义。Reasonix 可以实现测试，但不能自行决定什么足以签最终 PASS。
- 静态门只证明调用位置、符号或结构；运行时顺序必须使用可执行 spy、fixture 或真实环境验证。
- timeout、轮询和重试测试注入 clock、sleep 与 timeout；设置秒级预算，禁止 no-op sleep 配真实
  Date.now 导致墙钟忙等。
- 关键任务保留工作区外的独立判分器。执行者知道公开合同，但不能读取隐藏 fixture。
- 原始命令、退出码和耗时优先于自由文本总结。执行者的测试通过只推进到 SELF_TESTED。

## 6. 返工与会话

正常返工继续原 session，以保留实现上下文；每轮只退回一个同源不变量或一个原子反例。

出现以下情况时先由调度者生成新的当前事实快照：

- rebase 后依赖或行号发生变化；
- 合同、范围或架构裁决发生实质变化；
- 连续两轮仍重复同一类语义错误；
- 报告沿用已被反例推翻的旧表述。

事实快照必须明确哪些旧假设已失效。若旧上下文继续污染结果，创建新 session，并记录其来源
session、基线和未完成项；不要无限续聊，也不要让新 session 读取旧执行者的判分器或日志。

## 7. 并发

并发前先画依赖关系与写集：

- 只有无依赖或依赖已冻结的任务才并发；
- 每个写任务使用独立 worktree；
- 写集重叠的任务串行，或先明确唯一文件所有者；
- 禁止两个 session 同时写同一 worktree；
- 合并顺序由调度者预先确定；rebase 冲突由明确的文件所有者处理；
- ACP 的 emit、trace 和判分器全部写到工作目录外。

## 8. 交付状态

- **SELF_TESTED**：任务内自测全部按合同运行；仍需实际 diff 主审和独立验收。
- **BLOCKED**：缺少实质裁决、权限、事实或依赖；没有越权选择。
- **FAILED**：实现或自测未达到合同；保留原始失败证据。
- **REVIEW_REQUIRED**：由调度者在检查实际 diff 后标记。
- **ACCEPTED**：仅由独立验收者标记。

不要把 SELF_TESTED 改写成“全部闭合”“可以合并”或“用户已确认”。
