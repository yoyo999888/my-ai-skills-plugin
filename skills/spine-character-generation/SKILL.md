# Spine 角色生成与动态验收

目标是可编辑、可驱动、可追溯的角色资产。骨架约束运动结构；角色身份、体积、材质、完整部件和视角仍需设计。不要把原模板换色计为独立新角色，也不要把 Runtime 加载成功当作动态美术验收。

## 先确定输入和复用承诺

1. 盘点实际文件：只有骨架／关节、骨架加动作库，还是含 slots、skins、附件、完整贴图、网格、UV、权重和状态的完整模板。逐项记录缺失；不从“有骨骼”推断“有完整模板”。
2. 从资产和工具锁定 Editor／Runtime 版本与来源提交。不要靠改 JSON 的版本字段伪装兼容。`.spine` 需要实际可用的编辑器或合法导出链路，不能假定能直接读内部结构。
3. 无模板时继续研究和定义数据，尽早询问最关键输入；可用许可明确的示例或自制简单模板验证，标出不能外推的边界。
4. 判断用户要相近外观复用还是独立设计。明确哪些骨架、动作、约束、挂点、事件需要保持。用户要求原样复用时，发现不兼容就交付失败证据和具体适配选项，不能静默替换为新绑定。
5. 外观来源、骨架动作来源和 Runtime 许可分别记录。没有提交旧人物图片只能证明生成输入的隔离，不能保证法律上的原创或商用权利。

| 变化 | 优先路线 | 必须重新检查 |
|---|---|---|
| 配色、材质、图案 | 固定完整部件编辑，可复用原绑定 | alpha、受保护区域、跨部件一致性 |
| 相近轮廓装备 | 在锚点、轮廓和 UV 容差内适配 | 裁切、关节重叠、装备刚性、握持 |
| 明显轮廓／身体比例变化 | 独立设计、完整部件、新几何或新绑定、动作重定向 | 重新声明复用范围，动态重验 |
| 长发、披风、裙摆 | 增加完整层、辅助骨或网格，必要时另建模板家族 | 二次运动、遮挡、权重和压力姿态 |
| 身体拓扑变化 | 换模板或重新绑定 | 不承诺同一模板零适配 |

“换皮”和“独立外观＋新绑定／重定向”都可能合理，但须按用户目标选择，并分别统计。

## 设计、生成、装配

实现前读 [生成与绑定](references/generation-and-binding.md)：内含资产契约、提示词模板、锚点计算及视角状态处理。

- 独立角色先建立整体设计与体型，再生成完整部件及隐藏区域。完整运动部件不等于当前可见分割；切口延长几像素不等于补画完整肢体。
- 标定新图自身的关节和握持锚点。固定比例设计使用等比缩放；不要靠非等比拉图或随意拉骨长塞进旧模板。部件各自等比仍不足以保证整体头身比，应保留设计参考对照。
- 选择最小可解释实验，先打通一个角色；若任务要求 3／10 个角色，则后续按相同标准扩样，不能用换皮变体或同角色多轮返修充数。单角色仅是阶段结果。
- 调用生图前读环境中实际可用的生图技能，核实接口；设置次数、超时和重试上限。保存请求、模型标识、提示词、提交参考、原始响应、原图、耗时和失败。服务没有确认的 mask、seed、尺寸或透明能力均视为未知。
- 原区域必须保留时用程序合成／约束检验保证。新补画注明推测性补全，不称为恢复原始隐藏内容。响应尺寸和 alpha 均需解码核实。
- 能复用的结构应保留；确需重新绑定时，交付源到目标映射及已丢弃／已烘焙／待迁移项。动作中的 alpha、附件、层序、IK、约束和事件都要盘点，不能只取骨骼旋转。
- 硬质工具适用刚性附件和固定握持关系；软衣物需相应网格／骨骼。不要用整个角色逐帧换图冒充骨架动画。

## 用动态证据驱动返修

制定门槛、实现检查或判断“通过”前读 [动态验收与交付](references/validation.md)。

保留每次失败，定位到 **生成 → 后处理 → 锚点／比例 → 绑定 → 状态迁移 → 播放器** 的具体阶段。只在缺口确属画面内容时增加生成调用；装配失真先修装配，不盲目重画。

至少验证官方对应版本 Runtime 的实际输出、关键帧间插值、附件切换边界、关节压力姿态、刚性与握持、可见轮廓、白黑彩底和真实 UI 操作。实际看图和动态序列；几何、alpha、IoU 或 PSNR 单独通过均不能代表动画质量。视角强制切换等网页调试补偿须与导出动作区分，不能只靠预览层修好问题。

只读 PNG 检查可用附带脚本（需 Pillow）：

```sh
python3 <技能目录>/scripts/inspect_png_alpha.py <部件目录> --require-transparency --report <检查结果.json>
```

需要完全透明背景像素时加 `--require-clear-pixels`；只有明确为实心材质时才加 `--require-opaque-pixels`。默认只报告近不透明像素，不自动把玻璃、薄纱或特效判错，不修改输入。存在透明像素也不能证明整个背景干净；脚本不能判定接缝美观或版权。

## 收尾与报告口径

- 交付独立 PNG、结构化配置、版本匹配的 Spine 数据／图集、官方 Runtime HTML、质量和来源记录、可重放的处理／装配脚本。需要离线时验证 `file://`，不要仅假设内联了代码就不请求外网。
- 具备 Editor 时验证导入、保存、重开；只生成 JSON 就只声明 JSON／Runtime 交付。目标引擎按任务范围验证，用户只要求 Runtime 时不要强加引擎选择。
- 明确区分论文／官方资料、实际测得、工程假设和未验证。比较论文时核查当前代码、权重、许可和人工工序；项目页存在不等于方法可运行。研究线索见 [实验教训](references/r17-lessons.md)，旧核查不能当新项目的当前状态。
- 分开记录生成调用、失败重试、自动处理、人工操作计时、未通过资产分摊和维护。没有人工基线／账单时保留空值，不编造降本比例。
- 在独立目录从保存的原始输入重建，核对关键输出 hash；分离生图与重放，图集排序包含稳定的同高次序。打包不夹带不需要发布的原角色图、密钥或机器缓存。
- 明确技术通过与美术签收、研究原型与量产结论的差别。不要把“自主推进”理解为无限生成、无限扩样、自动发布游戏资产或静默缩小成功标准。
