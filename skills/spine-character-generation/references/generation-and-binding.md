# 生成、资产契约与绑定适配

设计独立角色、补件或选择复用方案时阅读。下列坐标与流程是可选择的工程表达，不限定骨骼数量、角色题材或 Spine 版本。

## 资产契约

把这些字段存入版本化 JSON／YAML；记录值的来源，不用图片文件名隐式表达全部语义。

| 对象 | 最少信息 |
|---|---|
| 模板 | 版本、单位、坐标、标准姿势、骨骼层级、目标动作和压力姿态 |
| 部件 | 稳定 ID、身体侧身份、视角、完整 RGBA、关节及握持锚点、重叠区域、允许变化区域 |
| 附件 | slot／skin／路径、绘制顺序、局部变换、挂点、视角状态 |
| 网格（若有） | 顶点、三角形、UV、权重及复用条件；无 mesh 的 region 不伪报蒙皮检查通过 |
| 状态与动作 | 来源映射、时长、附件与 alpha、draw order、约束、事件，逐项标记保留／改写／烘焙／丢弃／未验证 |
| 来源 | 设计、原始生成、后处理、锚点设定、人工修改和许可证范围，含输入与输出 hash |

左／右用角色身份或稳定 A/B 表示。不要把画面左右直接当人体左右；若无法确定解剖侧，记录来源链及持工具侧，不臆断。前后视角变化不能交换部件的身份。

最小锚点示例（演示数值，不是默认模板）：

```json
{
  "part_id": "upper_arm_A",
  "view": "front",
  "png": "parts/upper_arm_A.png",
  "pixel_coordinates": "origin top-left, x right, y down",
  "pivot_px": [20, 32],
  "distal_joint_px": [116, 32],
  "units_per_pixel": 0.2,
  "attachment": {"kind": "region", "uniform_scale": true},
  "source": {"kind": "generated_completion", "run_id": "recorded-run"}
}
```

允许的比例范围需要实测或来自生产模板规范。不要把一个机器人成功的长度比写成所有人形可用的区间。

## 生成选择和提示词

| 路线 | 适用情况 | 主要失败 |
|---|---|---|
| 固定完整部件编辑 | 明确接受模板外观范围，优先完整绑定复用 | 误称新角色、版位漂移、新轮廓被旧 alpha／mesh 裁掉 |
| 整体设计后拆层／补全／配准 | 先要求独立设计身份 | 可见分割缺隐藏区，左右与锚点不稳定，拆层不等于可绑定 |
| 整体参考＋定位＋相邻上下文生成部件 | 已知道需要哪些完整运动部件 | 接缝、材质、光照、尺寸和关节位置不一致 |

先针对一个已知缺口做最小比较，尽量固定设计要求、动作集、预算和返修标准。模型没有精确 layout／mask 能力时，不把定位板约束描述成像素硬锁。

```text
为参考中的独立角色生成 {完整部件／视角补件}。
身份与风格：{头身比例、形状语言、主材质、配色、线条、光源方向}。
参考图：{整体设计}；结构板：{只含允许使用的部件与定位上下文}。
目标：{稳定部件 ID、身体侧、视角、近端关节方向、远端方向}。
绘制完整轮廓，包括运动后暴露的 {关节／腋下／衣内／背部}，保留连接重叠。
不要连带相邻肢体；{手与工具分别绘制，并说明握柄位置}。
请求真实透明背景，不绘制标签、网格、地面或整角色复制。
若有不可改区域：{精确说明，并在后处理阶段程序合成保证}。
```

把请求当意图，逐项检查实际结果：尺寸、部件数量、alpha、方向、设计一致性、完整性。PNG 解码为 RGBA 也可能完全不透明；把 RGB 图片转换为 RGBA 并不会自动得到前景 alpha。

若用色键提取新图 alpha，记录底色、材料不包含该颜色的假设、反混色步骤及失败区域。最大连通域会删掉分离的头发／装饰；像素收边会吞掉细线；近不透明归一会损伤玻璃／发光层。只有满足具体材质与结构条件时采用，不做通用固定过滤链。

## 按新图锚点装配

设近端像素锚点为 `p`，远端为 `q`，PNG 为 y-down，骨架为 y-up。等比因子 `s` 下的骨段向量为 `s * (q.x-p.x, p.y-q.y)`，长度是其模。以这一长度设置新骨段，局部旋转补偿图中骨段方向。附件中心由图中心相对锚点的位移计算，而非目测把矩形中心放上去。

如果要求保留旧骨长，可通过等比缩放匹配锚点距离，但必须重新看整体体型和关节粗细；不能分别缩放宽高。若新设计要求与旧骨长互相冲突，明确判为需要适配或更换模板。

机械外壳和工具适合刚性单骨 region。不能因为附件只绑一根骨就宣称它始终刚性：父级 scale、shear、镜像和继承设置仍会作用于最终世界变换。测渲染后的边长、夹角和连接关系。

手的腕点与握持点是不同约束。工具锚点应与画出的握柄位置重合；闭手握固定工具时应验证相对旋转和接触点，而不只看工具是否跟随同一骨。持盾、松手、换手等需要不同状态，不强套固定角度。

## 重定向与状态语义

重定向时可从来源 Runtime 采样关节方向，按目标父子层级重构局部旋转，使用目标角色的固定长度。记录曲线重建、滤波、位移缩放、接地调整及其理由。平滑和高频采样是适配工具，不是通用必要参数；快速击打的峰值可能被滤波抹掉。

恢复动作语义至少查看：

- 可见性／alpha：隐藏阶段可能有任意骨骼换位，显露它们会制造错误飞跃。选择代表 slot 前，检查多个身体和装备层是否真的共享 alpha。
- 附件和层序：正背面不等于镜像；头、身、盾可有独立视角。离散正背图不能保证连续转身，应根据镜头和速度增加侧面状态。
- IK、约束、挂点与事件：保留求解器、烘焙其结果和丢弃约束是三种不同交付；不能因动作名称相同就称游戏逻辑兼容。
- 地面和接触：最低可见轮廓可辅助防穿地，但不是脚底接触求解。工具低于脚会改变最低点；需要脚锁定、滑步和支撑标签时另做约束。

不要把跨角色动作风格匹配混入几何成功率。一个机械角色可正常播放武侠招式，但仍可能不符合角色身份和重量感。
