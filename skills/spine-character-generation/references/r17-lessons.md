# R17 案例：哪些结论可复用

来源是 2026-09-22 的本地 Spine 独立角色实验记录。原始游戏资产、生成图片和完整实验工程不随本技能发布；本文件是经验摘要，不是可单独复现实验的完整数据集。下面数字仅属于该角色与该环境。

## 三个阶段

| 阶段 | 实际完成 | 学到的边界 |
|---|---|---|
| 10 个换皮样本 | 成熟人物模板的外观后处理和运行验证 | 原图、轮廓与绑定限制保留较多，不能计为 10 个独立新角色 |
| 第一个独立机器人版本 | 独立设计与部件；原 131 骨骼和 21 动作；651 姿态 Runtime 检查 | 大腿图片长宽比约 1.56，附件变成约 2.49；106 姿态触发缩放／倾斜诊断；独立生图仍会被错误装配破坏 |
| 第二轮同一机器人 | 新图锚点、新 17 骨骼、16 slots、21 张实际引用 PNG、31 附件；21 动作重定向，另有标准姿势与展示动作 | 修复刚性和握持，补全正背；代价是新绑定和新曲线，不能继续声称原绑定原样复用 |

独立角色累计只有 1 个。保留全部失败阶段，未完成 3／10 个独立角色的量产试点。

## 几个不直观的失败

- 来源 `attack4` 约 0.9–1.87 秒为全身隐身换位。只迁移骨骼会把隐藏运动显露成飞跃；核对多个身体与工具 slot 的共同 alpha 后恢复状态。
- 原生 RGBA 的生成补件内部多为 alpha 253，含红黄碎边。因这些部件是实心装甲，采用近不透明归一及边缘清理；这不适用于玻璃、薄纱或所有绘画风格。
- 请求 1024×1024，实际返回 1254×1254。请求字段不能代替实际解码。
- 透明矩形最低点约 -8.349 单位，但实际可见轮廓最深穿地约 0.044 单位。透明包围矩形会产生明显误报。
- 手动背面预览需约 3.255 单位接地补偿；记录为网页调试行为，自动播放偏移为 0。不能把预览修正偷偷归功于导出动画。
- 正背视图补齐后仍有转身跳切，武侠来源的交叉腿姿态也仍不符合所有机器人表演需求。数字通过没有消除动作设计问题。

## 文献如何服务工程决策

以下只是调研入口。使用时重新核查代码、权重和许可，不把 2026-09-22 的状态写成当前状态；本实验没有运行这些学习方法。

| 线索 | 借鉴位置 | 区别 |
|---|---|---|
| [Textoon](https://arxiv.org/abs/2501.10020)／[仓库](https://github.com/Human3DAIGC/Textoon) | 模板布局和完整组件约束生成 | Live2D 参数不等于 Spine 权重；模板限制也限制设计自由度 |
| [SPIRITUS](https://arxiv.org/abs/2503.09127) | 受控设计、分层、绑定与动作迁移流程 | 当时未确认可复现的公开实现，不作为现成交付依赖 |
| [See-through](https://arxiv.org/abs/2602.03749)／[仓库](https://github.com/shitagaki-lab/see-through) | 语义完整层与遮挡补全 | 完整层不保证符合目标关节拆件 |
| [Qwen-Image-Layered](https://arxiv.org/abs/2512.15603)／[仓库](https://github.com/QwenLM/Qwen-Image-Layered) | RGBA 分层对照 | alpha 层不等于稳定部件身份、锚点或绑定 |
| [Bunraku](https://arxiv.org/abs/2607.27348)／[仓库](https://github.com/SparcAI-Inc/Bunraku) | 可编辑结构表达 | 当时仓库仅 README，不能按网页演示宣称可部署 |
| [APES](https://github.com/zhan-xu/APES) | 仅有多姿态旧图时辅助拆件 | 已有完整骨架动作时优先级较低，不代替新部件生成 |

优先级由正在解决的缺口决定。已经有成熟绑定时，先研究完整部件与模板兼容；新设计突破原体型后，语义锚点、视角与重定向更关键。不要为凑论文数量扩大研究，也不要把流程借鉴称为论文复现。
